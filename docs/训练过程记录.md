## 一、实验总览

三次训练**固定随机种子 42**，因此初始权重完全相同，**唯一变量是优化器与学习率**。

| # | 配置 | 末轮 train acc | 末轮 val acc | 最佳 val acc | 结论 |
|---|---|---:|---:|---:|---|
| 0 | SGD lr=1e-4, momentum=0.9 | 0.2973 | 0.2939 | 0.3186 | ❌ 完全没学到 |
| 1 | **Adam lr=1e-4** | 0.7687 | 0.6749 | **0.6946**（epoch 12） | ✅ 最优 |
| 2 | SGD lr=1e-2, momentum=0.9 | 0.7023 | 0.6732 | 0.6732（epoch 15） | ✅ 收敛，略逊 |

**最终提交模型**：实验 1（Adam），test 集准确率 **71.28%**。

**一句话结论**：调参的优先级不是"选哪个优化器更优"，而是**先确认超参数之间是否配对**。
配对错误带来的差距（约 38 个百分点）远大于优化器之间本身的差距（约 2 个百分点）。

## 二、统一训练配置

| 项 | 取值 |
|---|---|
| 数据集 | train 2425 / val 609（每类各 20%，分层） |
| batch_size | 32 |
| epochs | 15 |
| 损失函数 | `nn.CrossEntropyLoss()` |
| 随机种子 | 42 |
| num_workers | 2 |
| 计算设备 | CUDA（RTX 5060 Laptop） |
| 单轮耗时 | 约 70 s（总计约 17 min / 组） |

**训练循环五步**（顺序不可换）：

```python
for inputs, labels in loader:
    optimizer.zero_grad()               # ① 清梯度（backward 是累加，不是赋值）
    outputs = model(inputs)             # ② 前向
    loss = criterion(outputs, labels)   # ③ 算损失
    loss.backward()                     # ④ 反向传播
    optimizer.step()                    # ⑤ 更新参数
```

**两处开关**：训练前 `model.train()`，评估前 `model.eval()`。
`eval()` 漏掉的后果：验证时 Dropout 仍在随机丢弃，
`if val_acc > best_val_acc` 保存下来的会是"**运气最好的一轮**"而非真正最优模型。

## 三、实验 0：SGD lr=1e-4 —— 一次「模型不学习」的完整诊断

### 3.1 现象

```
epoch  1/15  train loss 1.6099  acc 0.1769 | val loss 1.6098  acc 0.1823
epoch 15/15  train loss 1.6010  acc 0.2973 | val loss 1.6007  acc 0.2939
```

### 3.2 两条关键证据

**证据 A：loss 几乎没动。**
15 轮 1140 个训练步，loss 只从 `1.6099` 降到 `1.6010`（降幅 0.0089）。
而 `ln(5) = 1.6094` 正是"五分类瞎猜"的损失值 ——
说明模型输出几乎仍是"五个类各 20%"的均匀分布，**参数压根没被推动过**。

**证据 B：train acc ≈ val acc。**
`0.2973` vs `0.2939`，两个数几乎一样。

> 这一步的**判读方法比结果更重要**：
> - 若 train 高、val 低 → **过拟合**（模型记住了训练集，没学到规律）；
> - 若 train 和 val 都低（本例）→ **欠拟合**（模型连训练集都记不住）。
>
> 本例是欠拟合，所以**问题不在数据、不在网络结构**，只能出在"参数有没有被推动"上。

### 3.3 根因：学习率与优化器不配对

| 优化器 | 怎么决定每步走多远 | 常用 lr |
|---|---|---|
| **Adam** | 按每个参数的梯度历史**自动缩放**步长，所以能吃很小的 lr | 1e-4 ~ 3e-3 |
| **SGD** | 完全按给定的 lr 走，**没有任何自适应** | **1e-2 ~ 1e-1**（配 momentum） |

`lr=1e-4` 是给 Adam 的量级；配给 SGD 相当于"**开着一辆没有油门辅助的车，却只踩 1% 的油门**"——
差的不是 10%，是 100 倍。

### 3.4 修法与验证

两条路（见实验 1 / 实验 2）：

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-4)                    # 路线 A
optimizer = torch.optim.SGD(model.parameters(), lr=1e-2, momentum=0.9)       # 路线 B
```

两条都跑通了，**验证了根因确实是 lr 而非" SGD 不行"**。

### 4.2 观察

4. **训练集 acc（0.7023）低于 Adam（0.7687）** → SGD 在小数据量上"记得更少"，
   这正是它泛化有时更好的原因，但在 15 轮的预算内还没体现出来。

### 6.3 后续可做的实验（尚未做）

1. **Adam @ 25 epochs** —— val 到末轮仍上升，加轮次大概率还能涨；
2. **SGD @ 25 epochs** —— 同理，且 SGD 曲线更稳，长跑表现值得看；

4. **Adam lr 扫描**（3e-4 / 1e-3）—— 确认 1e-4 是否就是最优点。

## 七、训练相关的踩坑记录

### 7.1 验证集准确率偏低 ≠ 验证集的问题

**误判**："为什么验证集准确率这么低？"
**实情**：train acc 0.2973 ≈ val acc 0.2939 —— **两边都低**，是欠拟合，不是验证集被"区别对待"。
判读口诀：**先看 train 和 val 差多少，再判断是过拟合还是欠拟合。**

### 7.2 曲线图右边空白 —— 「陈图」陷阱

**现象**：训练完成后生成的曲线图，Accuracy 子图有条线，**Loss 子图整块空白**。
代码复查并模拟运行正确（两个子图各 2 条线）。

**根因**（时间戳钉死）：

```
evaluate.py 保存时间      22:40
训练进程启动时间          ~22:37      ← 早了 3 分钟
曲线图生成时间            22:55
```

**Python 启动时只 import 一次模块** —— 进程跑起来之后再改文件，**正在运行的进程毫不知情**，
用的还是 import 那一刻的旧版本。

**规律**：**改完代码必须重启进程才生效。**

**加固**：`train.py` 现在把训练历史落盘为 json，并提供 `compare_history.py` 从 json 重画 ——
以后重画曲线不必重训，也就不会再撞这个坑。

### 7.3 训练耗时异常的两轮

epoch 11 用了 684.9s、epoch 14 用了 1993.2s（其余约 70s）。
原因是那段时间电脑休眠/挂起，而 `time.time()` 把挂起时间也算进了"这一轮耗时"。
**不影响训练结果**，只是计时被污染。

### 7.4 解释器选错

截图里出现 `C:\Users\Henry\AppData\Roaming\uv\python\...\python.exe` ——
**不是项目的虚拟环境**，那里没装 torch，会报 `ModuleNotFoundError: No module named 'torch'`，
极易被误判成"环境坏了"。

**规矩**：本项目**永远用全路径** `D:\ML\.venv_gpu\Scripts\python.exe`，不要裸敲 `python`。
